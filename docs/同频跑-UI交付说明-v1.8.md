## 三、关键产品决策与实现说明

### 1. 双层表达（对外中性 / 站内专属）
- **对外分享卡与外层邀请**：无品牌名、无彩虹、无 Slogan、无头像昵称，只有时间 · 距离 · 城市 · 人数，落到任何群里都不暴露身份。
- **站内**：品牌视觉、Slogan、彩虹、成员信息完整呈现，专属感来自氛围与准入。
- 这一条是过审与用户安全的共同底线，**不随品牌强化而改变**。

### 2. 隐私与安全（P0，不向增长指标让步）
- 不拉取微信真实头像与昵称，头像为系统生成几何图形 + 彩虹环。
- 每个跑友卡、每条动态都有举报入口（人工 24h 处理）与双向屏蔽。
- 不获取实时位置、不上传轨迹（见下条）。

### 3. 定位：两种能力分开用
- **打卡一次性定位**：仅当用户点击「获取当前位置」时调用 `wx.getLocation({type:'gcj02'})` 读取一次，用于城市归属与城市点亮；明确声明不持续追踪、不上传轨迹、动态与榜单只显示城市、不展示精确坐标。
- **集合点地图选点**：发起陪跑时调用 `wx.chooseLocation` 打开微信内置地图选点，返回 POI 名称 / 地址 / 经纬度，保证大家到的是同一个具体位置；线下场未选点不允许提交；只存集合点，不共享任何人的实时位置。

### 4. 提醒：微信订阅消息
- 发起面板默认开启「开始前 1 小时 · 微信订阅消息」，发起成功即自动订阅。
- 场次详情「提醒」卡可分别订阅 **开始前 1h** 与 **本场结束**。
- 说明文案已写明「订阅消息需逐次授权，一次订阅对应一场；云函数在开跑前 1 小时定时触发推送」。

### 5. 取消机制
- **发起人**：可见「报名的人」卡片（人数、已打卡数、每人加入时间与打卡状态）；可「取消这场活动」，确认弹层写明「已报名的 N 位跑友会收到通知」；取消后全场置灰、显示「已取消」、按钮禁用。
- **参加者**：可「取消参加」，退出后其他人看不到「已退出」记录，可随时重新加入。

### 6. 发起入口重构
- 两类动作明确分开：**陪跑场次**（一次性：距离 / 时间 / 集合点 / 配速 / 人数上限 / 线上异步 or 线下约跑）与 **队伍**（长期：队伍名 / 常跑距离 / 时段 / 入队方式），表单内直接写清两者区别。
- 入口：首页底部 ＋ 按钮（主）、陪跑区块标题「＋ 发起 ›」、去跑页按钮、跑友页右下角 ＋（直达创建队伍）。

### 7. 备案名口径
- 判断：小程序备案管的是**名称 / 简介 / 服务类目**，页面内文案不属于备案名称；但显著位置出现第二名称，存在被认定「实际使用名称与备案不符」的整改风险。
- 处理：中文「同频跑」为唯一主名称，英文 `Rainbow Running` 降级为 10px 灰色副标；如需彻底规避，可只在「关于 / 设置」页展示。

## 五、技术接口清单（原型中已标注调用点）

| 能力 | 接口 | 用途 |
|---|---|---|
| 地图选点 | `wx.chooseLocation` | 发起陪跑时选集合点（POI 名 / 地址 / 经纬度） |
| 一次性定位 | `wx.getLocation({type:'gcj02'})` | 打卡时读取一次，判断城市归属 |
| 订阅消息 | `wx.requestSubscribeMessage` | 开始前 1h 提醒、本场结束提醒、活动取消通知 |
| 选图 | `wx.chooseMedia` | 上传成绩卡截图 |
| 内容安全 | `security.mediaCheckAsync` | 图片检测（替代已下线的 `imgSecCheck`） |
| 文本安全 | `msgSecCheck`（或云调用） | 动态、昵称、队伍名检测 |
| 太阳码 | `wxacode.getUnlimited` | 队伍邀请码（带参数） |

> 注意：`wx.chooseLocation` / `wx.getLocation` 需在 `app.json` 的 `requiredPrivateInfos` 中声明，并在提审时说明用途——「仅用于集合点选点 / 一次性城市归属判断」比笼统的「用于定位」更容易过审。

## 六、仍需注意的风险（与 UI 无关但影响上线）

1. **过审后复查下架风险**：提审材料主打同城跑步打卡，但站内实际为社群定位，存在被举报后复查整改甚至下架的风险。建议补充：主体隔离、用户数据可导出、社群备用触点。
2. **PIPL 敏感个人信息义务**：社区成员身份很可能落入敏感个人信息，需要**单独同意**（不能藏在通用协议里）与**个人信息保护影响评估（PIA）**记录。
3. **北极星指标缺度量机制**：「线下同跑人次」目前无采集手段，建议定义代理指标（如线下场报名 → 赛后互相鼓励/评论率）。
4. **打卡漏斗断点**：跑完人在户外、小程序已被杀，建议依赖「开始前 1h / 本场结束」订阅消息召回。
5. **MVP 排期**：举报 / 屏蔽 / 内容安全应作为 P0 与动态功能同期交付，不应放到收尾阶段。

## 七、原型使用说明

- 直接在浏览器打开 `同频跑-最终UI-v1.8.html`，左侧为手机框（可内滚、可切 Tab），右侧为版本说明。
- 可交互：五 Tab 切换、加入/发起陪跑、地图选点、打卡定位、订阅提醒、发起队伍、取消活动/取消参加、举报与屏蔽、加油与鼓励、搜索与邀请（外层/内层对比）。
- 所有数据为 mock，口径与 PRD v1.2 一致（「今天 / 累计」，无实时定位）。
