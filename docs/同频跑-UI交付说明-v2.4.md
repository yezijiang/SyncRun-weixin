## 三、v2.2 → v2.4 补充（最新）

### 1. 品牌命名：同频跑 pride running 🌈（v2.4）

**最终决定**：中文名保留 **同频跑**，英文名 **pride running**，站内展示为「同频跑 pride running 🌈」。

**为什么中文名改回「同频跑」**（推翻 v2.4 中途的"派莱德"方案）

| | 派莱德（Pride 音译） | 同频跑（最终采用） |
|---|---|---|
| 可理解性 | 三个字看不出是做什么的，用户搜不到、记不住 | 自带语义（同频 + 跑步），一眼知道是跑步产品 |
| 与 Slogan 的关系 | 切断——"跑起来，遇见同频的人"失去语义锚点 | 同源——"同频"双关：既指志同道合，也指配速同频 |
| 搜索与传播 | 纯音译，口碑传播时难拼写 | 中文可直接搜索、口述 |
| 中性安全 | 中性 | 同样中性（工商与备案层面无任何社群指向） |

核心理由：**音译名解决了"不暴露"，却牺牲了"被找到"。** 「同频跑」在工商与备案系统中同样是纯中性的中文名，不存在暴露问题，因此音译带来的那点额外安全性换不来可理解性的损失。

**代价（要认，也要应对）**
- **商标显著性弱**：「同频 + 跑」属描述性组合，注册难度高于臆造词，也较难阻止他人近似使用
- 应对三条：① 尽早在中国商标网检索第 9 类（软件）/ 41 类（体育文娱）/ 35 类（广告）并提交；② **把彩虹跑者 Logo 单独申请图形商标**（图形不受描述性限制，这是本案最有效的保护手段）；③ Logo 做著作权登记，作为兜底

**英文名的定位**：pride running 只承担**圈内身份表达**，不进工商、不在执照出现；是否进小程序备案名需决策（见下方风险提示）。

| 层面 | 看到的是 | 效果 |
|---|---|---|
| 工商公示 / 营业执照 | 同频跑（执照不得含外文） | 中性，看不出含义 |
| 小程序名与备案 | 同频跑 pride running | 中文是主名；英文是身份表达 |
| 审核员 | 需认得 Pride 才识别 | 存在一定识别概率 |
| 圈内用户 | pride running | 一眼就懂 |

**风险提示（需决策）**：只要英文名出现在小程序名里，备案时就可能要求以「同频跑 pride running」作为服务名称提交，**Pride 一词会永久留在备案记录中**。若对此有顾虑，保守方案是小程序名只用「同频跑」，pride running 仅出现在关于页与传播物料（不进备案名）。

**首页抬头（v2.4）**：品牌区为欢迎语 —— **「欢迎来 同频跑 pride running 🌈」**。「欢迎来」为浅灰小字前缀，中文名保持 17px 粗体主名，英文名 11px，末尾彩虹 emoji；下方仍为双语 Slogan 两行。欢迎页同步为「欢迎来同频跑 pride running 🌈」。

### 2. 品牌便签浮层（v2.4）
第一次使用时浮出的文艺便签，**是浮层、不是首页内容的一部分**（不占版面、不随页面滚动）：

> 🌈 同频跑 · pride running
> 这里是 LGBTQ+ 与女性友好的跑步社区。
> 你不必解释自己是谁，也不必跑得比谁快。
> 同一座城市，同一个傍晚，有人和你一起出发。
> 跑完回来打个卡，就知道今晚并不孤单。
> 互相鼓励，慢慢变强。运动这件事，终于**有人同行**。
> —— 跑起来，遇见同频的人

- 视觉：米黄便签纸（渐变 #FFFCF2→#FDF6E4）、微旋转 -0.8°、顶部胶带装饰、加重投影
- 触发：走完新手引导后延迟 400ms 自动浮出一次
- 关闭：点 ✕ / 点遮罩 / 点「收起」
- 底部按钮：「收起」与「了解这个社区 →」（直达关于页）
- 可控：安全中心「进入时浮出品牌便签」开关 +「重新看看这张便签」入口
- **为什么需要开关**：应对"肩膀冲浪"场景——用户在地铁、办公室打开小程序时，旁边的人可能看到屏幕。社群标签在站内是对的，但用户得有权决定何时展示

### 3. 「同场开跑」是约定人数，不是实时定位（v2.2）
用户诉求："此刻有 X 位跑友"是想让同城的人看到有多少人在跑，营造陪伴感——**这个诉求应该保留**，它是产品核心价值。

但口径必须诚实：不做实时定位，就无法知道谁"此刻真的在跑"。所以定义改为：

> **本时段 X 位跑友和你同场开跑** = 加入了同一开跑时段场次的报名人数

这是"约好一起跑"的约定，不是实测。落地三处：
- Hero 文案下方常驻小字：**「按开跑时段与报名人数推算 · 不使用实时定位 · 了解这个产品 ›」**
- 跑友区块名：**「今晚同场开跑」**（副标：已加入今晚场次的人）
- 跑友卡：显示「常跑距离 · 今晚 20:00 同场」，不再显示暗示实时的配速
- 「关于」页有完整口径说明

### 4. 集合点 = 地图选点（可搜索），不是"获取当前位置"（v2.2）
澄清：集合点从 v1.7 起就是 `wx.chooseLocation`（微信内置地图），支持搜索地点名、拖动地图、选附近推荐，**不是读取当前位置**。此前原型只给了一个固定 POI，造成误解。

v2.2 补出完整的选点界面：
- 顶部搜索框（输入地点名即时过滤）
- 地图缩略图 + 图钉（选中即标注）
- 附近 POI 列表（5 个，含地址与距离）
- **无匹配时可直接用输入的名称**作为集合点（不强制必须从列表选）
- 修复一个 UX bug：开始输入即清除旧选择，避免"输了新地名却用了旧地点"

真实能力备注：`wx.chooseLocation` 还支持拖动地图微调位置，返回 POI 名称 / 地址 / 经纬度。

### 5. 新增「关于同频跑」理念页（v2.2）
给第一次使用的人讲清定位、宗旨、愿景，以及**我们不做的事**（克制本身就是这个产品的信任来源）。

内容结构：
- **Slogan**：让每一次奔跑，都不必是一个人。找到和你同一时段、同一频率的人
- **我们的定位**：同城跑步陪伴社区；不是记录工具，不比配速，不排名次；核心是异步同行
- **我们相信**：陪伴不需要同时同地 / 安全感是前提不是选项 / 跑步没有门槛
- **我们不做**：不做实时定位与轨迹追踪 / 不自动读取微信头像昵称 / 不做排名与配速比较
- **数据口径**：「本时段 X 人同场开跑」怎么算的
- 版本与备案名称

入口三处：首页 Hero「了解这个产品」、新手引导「了解我们的定位与理念」、设置页「关于同频跑」。

## 四、v2.1 系统校正（挑剔复盘后的 6 项，v2.3 重构其中第 3 项）

### 1. 修正逻辑硬伤：不再谎称"实时"
原版写着「此刻有 128 位跑友正在奔跑」「此刻正在奔跑」——**但产品明确不做实时定位**，没有实时定位就不可能知道谁"此刻在跑"。这是自相矛盾，审核员或懂行用户一眼看穿。

已全部回落为"今天/累计"口径：
- 「此刻正在奔跑」→ **「今天跑过的跑友」**
- 「此刻有 128 位跑友正在奔跑」→ **「今天已有 128 位跑友完成打卡」**
- 跑友卡补充「今天跑的 · 配速 X」

### 2. 补齐冷启动空态
原版所有页面都是"满数据"状态，新用户第一天进来看到的是一片空白 + 无从下手。现在：
- 首页三块（跑友 / 场次 / 城市）均有空态插画 + 说明 + 引导按钮
- 统计条随空态归零
- 原型右侧提供**「活跃社区 / 新用户首日」演示切换**，两种状态可随时对比

### 3. 首次进入：隐私与运动风险声明（v2.1 新增，v2.3 重构）
运动类产品缺免责声明是硬伤。新增声明页（在引导之前，需勾选同意才能继续）：
- 位置使用说明（一次性读取、不追踪、不记轨迹、不实时共享）
- **运动风险提示与免责**（量力而行、夜间与陌生路段安全、平台不承担运动损伤责任）
- 未成年人提示（未满 18 岁需监护人同意）
- 设置页可随时重看

**v2.3 重构：从「风险告知」改为「我们为你做的事」。** 原版是"法务写的界面"——合规没错，但灰底条文让人有压力、想退出。改法是把同样的内容换个角度讲：

- 标题：使用前确认 → **「欢迎来同频跑 🌈 / 这里只有跑得开心这件事。开始之前，想先告诉你三件我们为你做的事。」**
- 三张柔和色卡片（珊瑚红 / 暖琥珀 / 柔绿，各带图标）：
  - 🔒 **你的位置，只属于你** — 只在你说"好"时读一次，用来点亮城市；不追踪、不记轨迹、不共享实时位置
  - 🎭 **你是谁，由你决定** — 头像昵称默认系统生成，不会自动读微信资料
  - 🌿 **跑你自己的节奏** — 不排名、不比配速，跑多远多快都不影响你被欢迎
- 法律必需的免责与未成年人条款**保留**，但缩为底部小字，不再抢视线
- 文案软化：按钮「同意并继续」→「进入同频跑 →」；勾选「我已阅读并同意…」→「好，我知道了 —— 也同意…」；未勾选提示 →「先点一下上面那行小字就好 🌱」
- **合规未削弱**：勾选仍是进入的前置条件（测试专门验证"未勾选仍不能进入"）

### 4. 消息中心可就地处理
原版消息只能"看"，现在每条带操作：
- 收到鼓励 → **👋 回一个加油**
- 约跑邀请 → **🤝 接受并加入**
- 有人报名 → **查看报名的人**
- 活动被取消 → **看看其他场次**

### 5. 发起即邀请（解决"发起了没人来"）
发起陪跑成功后**直接打开邀请页**（太阳码 / 站内邀请），而不是丢一个 toast 就结束。冷启动期"发起后无人报名"是最大的流失点，这一步把邀请变成默认动作。

### 6. 初始化一致性修复
安全中心黑名单区此前只在打开时渲染，已改为初始化即渲染（与其他区块一致，避免空白闪烁）。

## 五、核心产品决策（9 条底线）

1. **双层表达**：对外分享卡与外层邀请永远中性（无品牌名、无彩虹、无 Slogan、无身份信息），站内才呈现完整品牌与社群氛围。
2. **默认不识别**：头像昵称默认系统生成，不自动拉取微信资料；用户主动点选才用微信头像，并提示「会被熟人认出」+ 一键换回。
3. **位置最小化**：只在打卡那一刻读一次（城市归属 + 区街道，仅自己可见）；集合点用地图选点。
4. **不做实时轨迹追踪与实时位置共享**：技术可行但产品排除，记录交给 Keep / 咕咚 / Strava，用户以成绩卡带入。见**附录 A（ADR-001）**。
5. **推荐不按物理距离**：按跑步时段 → 常跑距离 → 周频次 + 近 7 天活跃；发动态不加权。
6. **数据口径诚实**：陪伴感要保留，但**不谎称实时**。"同场开跑"= 同时段场次的报名人数，并在界面上写明推算方式。
7. **身份表达可控**：社群标签（便签、彩虹、英文名）在站内默认展示，但用户必须能一键收起/关闭——应对"肩膀冲浪"场景。
8. **命名分层**：中文名「同频跑」在工商与备案层面完全中性、自带语义（优先保证用户找得到、记得住）；身份表达交给站内英文名「pride running」，不进工商信息。
9. **P0 不向增长让步**：举报、双向屏蔽、内容安全与动态功能同期交付。

## 附录 A：产品决策记录（ADR）

### ADR-001：不做实时轨迹追踪与实时位置共享

**状态**：已决策（2026-10-17）

**背景**：技术上微信小程序支持——前台持续定位（`wx.startLocationUpdate`）稳定可用；后台持续定位（`wx.startLocationUpdateBackground`）需 `requiredBackgroundModes: ["location"]` 声明、用户授予 `scope.userLocationBackground`、类目属于开放范围（运动健康 / 出行交通 / 生活服务）、并在后台手动开通接口；锁屏或切出微信后小程序会被挂起，长时间定位不可靠。

**决定**
1. 不采集、不上传跑步轨迹；不做实时位置共享
2. 定位仅限：① 打卡时用户主动点击一次性读取 ② 发起活动时地图选点
3. 不引入 `startLocationUpdateBackground`，不申请后台定位权限
4. 记录交给 Keep / 咕咚 / Strava，用户以成绩卡（可含轨迹图）带入

**理由**
1. 与"只在打卡那一刻读一次位置，不持续追踪"的承诺一致
2. 行踪轨迹在 PIPL 下属**敏感个人信息**，需单独同意 + PIA + 更高保管义务
3. 常跑路线、常驻区域、出入规律泄露可能危及未出柜用户的人身与职业安全
4. 该人群对"被定位"敏感度高，功能可能反伤留存
5. 不服务北极星指标（线下同跑人次），异步同行已能达成"一起跑"

**例外（V2 备选，需重新评审）**
若用户强烈要求"看自己的路线"，仅允许：前台记录（切后台暂停）→ 仅本地生成 polyline → 默认不上传 → 用户主动保存 → 任何情况不共享他人 → 支持一键删除。

**违反后果**
需重写隐私协议、补单独同意流程、重做 PIA、变更审核材料，并可能引发用户信任危机。任何改动须重新评审。

## 附录 A-2：ADR-002 品牌命名与身份表达分层

**状态**：已决策（2026-10-17），英文名是否进备案名**待用户确认**

**背景**
曾考虑改用 Pride 的音译「派莱德」以进一步降低工商层面的识别度，评估后放弃：音译名解决了"不暴露"，却牺牲了"被找到"——三个字看不出产品是做什么的，用户搜不到、记不住，且与 Slogan「跑起来，遇见同频的人」的语义锚点断裂。

**决定**
1. 中文名「同频跑」（保留），英文名「pride running」，站内展示为「同频跑 pride running 🌈」，中文在前、英文在后
2. 营业执照名称**只含中文**（《个体工商户名称登记管理办法》第十一条：不得含汉语拼音、字母、外国文字）
3. 经营范围与工商公示信息中**不出现**社交、交友、社群、彩虹等字眼
4. 身份表达（便签、彩虹、英文名）站内默认展示，但提供一键收起与开关

**理由**
1. 「同频跑」在国家企业信用信息公示系统中同样是纯中性中文名，不暴露产品定位；音译带来的额外安全性不足以补偿可理解性的损失
2. 「同频」双关：既指志同道合，也指配速同频；与 Slogan 同源，品牌语义自洽
3. "肩膀冲浪"是真实风险：用户在公共场合打开小程序时，屏幕可能被旁人看到，所以身份元素必须可收起

**已知代价与应对**
「同频 + 跑」为描述性组合，商标显著性弱：① 尽早检索并提交第 9 类 / 41 类；② **彩虹跑者 Logo 单独申请图形商标**（最有效的保护手段）；③ Logo 做著作权登记兜底。

**风险与备选**
若英文名进入小程序备案名，「Pride」将永久留在备案记录中。保守备选：小程序名只用「同频跑」，pride running 仅出现在关于页与传播物料。

**违反后果**
工商或备案信息暴露定位，可能在资质审批、复查或被举报时成为不利因素。
